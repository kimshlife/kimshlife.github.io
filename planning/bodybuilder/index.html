BodyBuilder 창작마당공개 정책·기능 범위 설계

공개할 수 있는 맵의 조건부터 설계하다.

맵을 만드는 자유도에 앞서 공개 조건, 제작 한도, 본 게임을 보호할 기준을 정했습니다.

2026.07–086인 팀 / 창작마당 전담
01

클리어 인증을 공개 조건으로 뒀습니다.

제작자가 직접 한 번 클리어한 맵만 공개할 수 있게 했습니다. 지형을 바꾸면 검증을 무효화하고, 포즈 변경은 무효화 대상에서 뺐습니다. 검증 상태는 에디터에 항상 보여주고, 미검증 상태에서는 공개 저장만 막도록 명세했습니다.

02

제작 한도는 공식 맵을 재서 정했습니다.

공식 맵 6개는 폴리곤 2–3개, 정점 4–6개, 기믹 0–2개 범위였습니다. 이를 바탕으로 폴리곤 8개·정점 20개·기믹 5개를 상한으로 두고 서버가 최종 검증하도록 했습니다. 첫 단계에서는 좋아요·평점·댓글을 분리해 핵심 제작과 공유에 집중했습니다.

03

구현이 되돌려준 정보로 명세를 고쳤습니다.

명세와 작업 지시를 v1–v9까지 수정했습니다. 구현 중 드래그 이동 경로에서 인증 무효화가 빠진 것을 발견해 보완했습니다. 에디터를 복제하라는 초기 지시는 유지보수 부담 때문에 한 컴포넌트의 분기 속성으로 바뀌었고, 그 차이도 기록했습니다.

설계 기록

항목을 펼치면 세부 판단과 원본 자료를 읽을 수 있습니다.

01설계 결정과 근거
결정근거
범위를 Phase 1로 자름프로토타입을 전부 반영하면 테이블 3개 · API 6개 · 인증 로직이 추가되어 범위가 두 배 이상. 핵심은 맵을 만들어 함께 노는 것이고 좋아요·평점·댓글은 Phase 2로 분리
시뮬레이션 타임아웃 초기안 폐기벽시계 타임아웃은 물리 엔진의 결정성을 깨 같은 입력이 같은 결과를 내지 못함 — 리플레이 재현성이 무너짐
예약 ID 대역 채택커스텀 맵을 별도 도메인으로 분리하는 안이 공식 게임 경로의 회귀 위험이 더 컸음
완료 기준을 문장으로“공식 게임의 동작을 바꾸지 않는다, 그 증거는 기존 테스트가 무수정으로 통과하는 것이다”
커스텀 맵은 1라운드3라운드를 강제하면 에디터에서 감당할 작업량이 과해짐 — 유저 부담 기준
썸네일은 팔레트 그라디언트이미지 업로드를 받으면 저장소와 검수가 따라옴. 색 세 개만 골라 스토리지 없이 카드가 구분되게
02명세 → 지시 → 구현
명세 규칙작업 지시구현 결과
공개 전 제작자 본인이 한 번은 클리어검증 상태 상시 노출, 미검증이면 공개 저장만 막음클리어 미검증 배지와 안내 문구
지형이 바뀌면 검증 무효화, 포즈 변경은 아님지형 편집 이벤트에만 무효화 연결드래그 이동 경로의 누락을 발견해 보완
에디터를 복제해 유저용을 만든다관리자 에디터 복사 후 경로·권한 교체지시와 다르게 구현 — 복제하면 버그 수정을 두 곳에 해야 해서 한 컴포넌트에 분기 속성
평점이 없을 때 0.0으로 쓰지 않음미집계는 대시로 표시0.0은 최저 평점으로 읽히므로 구분

공개된 맵은 본인과 팀원이 만든 것이라, 외부 사용자가 상한까지 썼다고 말할 수는 없습니다.
