  1. 문제

  2. 관찰

    30여 건을 12개 유형으로 묶고 빈도순 정렬 — 평가 담합·보복 투표 약 11건 1위

  3. 판단

  5. 검증

    플레이테스트 수치 검증은 하지 못함. 버그·건의 설문을 재현 가능한 형태로 설계해 다음 확인의 출발점을 만듦

상세 분석 보기 · 12개 유형 전체 · 허용한 결정과 청중 반응 · 대응 우선순위

01문제

SSketch는 낮에 그리고, 밤에 훔치고, 아침에 익명으로 평가하는 4인 파티 게임입니다. 점수는 그린 사람이 아니라 아침에 그림을 가진 사람이 받습니다. 기획안 발표 뒤 받은 피드백 30여 건에서 “점수가 왜곡될 것 같다”는 걱정이 표현만 바뀌어 반복됐습니다.

  • 내 그림을 도둑맞으면, 그 그림에 일부러 낮은 점수를 줄 것 같다 (5건 이상 중복)
  • 점수가 현재 소유주에게 가므로, 완성도가 아니라 ‘누구에게 점수를 주면 내가 유리한가’로 채점하게 될 것
  • 하위권끼리 담합하거나 1등 그림에 낮은 점수를 주는 전략이 나올 것

2위 6건(“그림을 왜 훔치나요?”)은 모두 기획서에 답이 있는 질문이었습니다. 소유권이 넘어가면 점수도 넘어간다는 규칙이 발표에서 전달되지 않았습니다.

03판단

① “허용하기로 한 것”이 결함으로 읽혔습니다.

기획서의 결정청중의 반응건수
담합·보복 투표는 정치질의 일환으로 허용공정성이 없다11
백지 전략도 전략의 일종으로 허용4등을 유지하다 역전하면 되지 않나1
동선 추적으로 정체를 추정하는 것은 허용익명성이 깨진다1

세 경우 모두 팀은 답을 갖고 있었지만 발표에는 없었습니다. 규칙만 설명하고 “왜 그렇게 두었는가”를 말하지 않으면, 듣는 사람은 미완성으로 받아들입니다.

② 하향 평준화 압력 — 실제로 검토가 필요한 지적

“잘 그리면 표적이 되고 빼앗기면 점수를 전부 잃으니 적당히 못 그리는 게 합리적”과 “일부러 4등을 유지하다 버프 아이템으로 역전”을 합치면 하나의 구조 문제가 됩니다. 절도와 러버밴딩이 같은 방향으로 작용해 ‘적당히 못하기’에 이중 보상이 걸립니다.

③ 판단을 보류한 것

“모두가 훔치러 다니는 걸 아는데 감속 페널티까지 있으면 절도 성공률이 너무 낮지 않나”는 타당한 걱정이지만, 맵 크기와 감속률이 정해지지 않은 시점이라 판단할 수 없다고 적어 두었습니다.

04행동

순위대응이유
1발표 자료 수정 — “훔친 그림의 점수는 도둑이 가져간다”를 별도 장표로, “의도적으로 허용한 것” 한 장 추가설계를 바꾸지 않고 지적 17건(1·2위)에 답할 수 있음
2설계 검토 — 원작자 점수 / 소유 점수 분리, 러버밴딩 지급 조건 재검토하향 평준화 압력의 근본 대응
3범위 판단 — 라운드 수 자유 선택, 인원 확장, 그림 저장저장 기능은 UGC 관리 의무가 따라붙음
  • MVP 발표에서는 지적마다 허용 / 장치 / 제작 중 / 미도입으로 대응을 나눠 답했습니다. 모든 지적을 고치겠다고 하면 일정이 무너지고, 답하지 않으면 같은 질문이 반복됩니다.
  • 그림을 든 사람의 운반 감속률을 10%에서 30%로 올렸습니다. 10%로는 느려진 것을 플레이어가 알아채지 못해 추격이 성립하지 않았습니다.

05검증

대응 효과를 플레이테스트 수치로 확인하지는 못했습니다. 대신 배포 뒤 받을 제보가 재현 가능한 형태로 들어오도록 설문을 설계했습니다.

  • 첫 질문에서 버그 제보 / 건의 사항으로 갈라 상관없는 질문을 건너뛰게 함
  • 버그 제보는 문제 유형, 로비부터 엔딩까지의 발생 시점, 스크린샷·영상을 받음
  • 모집글에 제보 요령(시간대·인원·방장 여부)을 함께 안내

기여 경계 — 방 만들기의 ‘인공지능 평가자’ 항목, 연막탄·섬광탄 구현은 팀원 작업입니다.

BodyBuilder · 이상한 현상을 재현 가능한 문제로

경사면을 걸어가는 캐릭터가 ‘떨어지는 중’으로 보였습니다.

상황vy프레임당 vy 변화
자유낙하계속 증가≈ +36
경사면 보행134 (클 수 있음)≈ 0
평지 보행≈ 0≈ 0

vy 크기로는 경사 보행과 낙하가 구분되지 않고, 변화량으로는 구분됩니다.

  1. 문제

    경사면을 걷는 캐릭터가 ‘추락’ 상태로 표시됨

  2. 관찰

    45° 경사를 내려갈 때 걷기 모터가 vy≈134를 유지 — 크기만 보면 낙하와 같음

  3. 판단

    구분 신호는 크기가 아니라 프레임당 변화량. 직접 쓴 명세 기준값은 맵 스케일을 무시해 최대 100배 차이

  4. 행동

    변화량 기준 + 최소 지속시간 필터로 교체, 모든 임계값을 맵 스케일로 정규화

  5. 검증

    회귀 테스트 14개 — 경사 보행 ≠ 추락, 두 스케일 같은 판정. 2026.10.06 재실행 14/14 통과

상태 표시가 틀리면 이용자는 실패 원인을 잘못 학습한다.
상세 분석 보기 · 재현 조건 · 기존 명세 · 오류 원인 · 수정 · 회귀 테스트 결과

01문제 현상

캐릭터 상태를 대기·전환·예비·이동·착지·추락·부유로 나눠 스프라이트를 붙였는데, 경사면을 걸어 내려가는 캐릭터가 계속 떨어지는 모션으로 보였습니다. 포즈로 만든 다리가 곧 지형이라 이 게임에서는 경사면이 대부분이어서, 오판이 상시 발생하는 문제였습니다.

선이 겹쳐 다리를 넘지 못했을 때 플레이어는 “선을 다 이었는데 왜 못 넘어가느냐”고 묻습니다. 실패 이유가 화면에 없으면 다음 시도를 어떻게 바꿔야 할지 알 수 없고, 상태 표시가 틀리면 엉뚱한 이유를 학습합니다.

02실제 플레이 영상

BodyBuilder 플레이 영상 보기 (YouTube) ↗

03재현 조건

  • 서버 물리 시뮬레이션은 매 스텝 vy += GRAVITY × dt를 더하고 충돌 때 법선 성분만 보정 → 접지해도 vy가 0이 아님
  • 걷기 모터가 경사 탄젠트 방향으로 걷기 속도 190을 밀어넣음 → 45° 경사 하행 시 vy ≈ 190 × sin45° ≈ 134
  • 재현: 경사면을 걸어 내려가는 구간이 들어간 라운드 한 판 — vy는 크지만 프레임당 변화량은 ≈ 0

04기존 명세

처음 작성한 작업지시서는 절대값 임계값(vx > 25, vy > 90)으로 상태를 나눴습니다.

05오류 원인

출처맵 좌표 범위예시 속도
실서버 물리 시뮬레이터0 – 1000vx ≈ 190
개발용 mock 서버0 – 10vx = 0.9
  • 같은 물리 현상이 환경에 따라 100배 다른 숫자로 들어옴 → 절대값 임계값을 쓰면 mock 환경에서 캐릭터가 절대 움직이지 않고, 특정 조건에서는 낙하 상태가 한 번도 나오지 않음
  • 정규화된 중력은 스케일과 무관한 상수여야 하는데, 임계값이 스케일에 딸려 커지고 있었음
  • vy 크기 기준 자체도 경사 보행을 낙하로 오인 (03)

06수정 내용

  1. 정규화 변화량 — dvy = (vy[i] − vy[i−1]) / mapWidth, 자유낙하 기준값 720 × 간격 / mapWidth의 절반을 넘으면 공중 후보
  2. 최소 지속시간 필터 — 공중 150ms · 지상 100ms보다 짧은 구간은 반대 상태로 되돌려 프레임 단위 깜빡임 제거 (실제 낙하는 짧아도 약 5프레임이라 지워지지 않음)
  3. 동작 배정 — 추락 → 착지(375ms) → 이동 → 대기 순 우선순위
  4. 재생 전 일괄 판정 — 서버가 궤적 전체를 한 번에 주므로 앞뒤를 다 보고 타임라인을 계산

부유(float)는 물리 상태가 아니라 실패 연출이라 타임라인에서 빼고 결과 판정으로만 띄웁니다.

02SSketch에만 필요한 것

  • 밤 밝기 — 밤의 어둠은 연출이 아니라 규칙입니다. 밝기를 무제한으로 올리면 익명성이 무너집니다.
  • 스테디 펜 속도는 설정에 넣지 않음 — 낮출수록 선이 매끄러워져 실력 차이를 지웁니다. 취향이 아니라 난이도입니다.
  • 보이스 채팅 — 입력 음소거 · 입출력 볼륨 · 마이크 장치 선택

최종 구현에서는 스위치를 ‘끔/켬’ 두 버튼으로 바꾸고, 주사율 · Y축 반전 · 밝기를 뺐으며, 화면 되돌림 확인 창은 해상도와 화면 모드를 바꿀 때만 뜨게 했습니다.

카운터사이드 · 같은 콘텐츠, 다른 경험

길드를 6년 운영하며 신규·복귀·숙련 이용자가 같은 콘텐츠를 다르게 겪는 것을 봤습니다.

장점 1 — 지속 플레이

  1. 캐릭터에 관심
  2. 외전에서 고유 스토리 탐색
  3. 배경 · 관계 이해
  4. 다음 이야기 기대
  5. 지속 플레이

세계관을 한 번에 풀지 않고 나눠 두면, 다음 업데이트를 기다릴 이유가 생깁니다.

장점 2 — 협력전

누구나 할 수 있는 아레나 → 아티팩트 → 레이드 숙련자에게 도움.
성장도가 낮은 이용자도 공동 목표에 기여할 수 있는 구조입니다.

문제레이드는 성장도에 따라 실제 참여 난도가 크게 달라짐 — 전원에게 요구하면 신규 이용자가 버티지 못함
실제 운영아레나 필수 / 레이드 선택 (일요일 이후)
개선 제안레이드 진입 전, ‘권장 준비 조건 ↔ 현재 상태’ 비교 안내
검증 계획안내만으로 준비 조건을 이해하는가? 어느 단계에서 진입을 포기하는가?
  1. 문제

    같은 레이드라도 성장도에 따라 참여 부담이 전혀 다름

  2. 관찰

    2020–2026 길드 「Time」 운영 · 2명 → 최대 30명 · 신규·복귀·숙련 이용자

  3. 판단

    아레나의 아티팩트가 숙련자에게 돌아가는 구조라, 각자 할 수 있는 것만 해도 서로 이득

  4. 행동

    길드 규칙: 아레나 필수 · 레이드 선택. 게임에는 진입 전 준비 조건 비교 안내를 제안

  5. 검증

    운영 규칙은 6년간 중재가 필요한 분쟁 없이 유지. 제안은 이해도·포기 지점 관찰로 검증할 계획

01무엇이 사람을 붙잡았나

  • 메인 / 외전 분리 — 메인 스토리는 세계관을, 외전은 캐릭터 고유의 이야기를 맡아 애착을 만듦
  • 장기적 빌드업 — 세계관을 한 번에 풀지 않고 나눠 두어 다음 업데이트를 기다릴 이유를 만듦
  • 몰입 강화 — 에피소드별 맞춤 음원과 연출

캐릭터 비주얼은 들어오게 만들고, 스토리는 남게 만듭니다. 이 게임에서 재방문을 만든 쪽은 후자였다고 봅니다.

02참여 격차를 운영으로 다룸

규칙이유
필참은 협력전 아레나 하나, 레이드는 선택레이드는 시작한 지 얼마 안 된 사람이 따라가기 어려움. 아레나의 아티팩트가 레이드 숙련자에게 도움이 되는 구조
레이드는 일요일 이후필참인 아레나가 평일 일정과 부딪히지 않게
미접 기준 7일길드 시스템의 주간 갱신 주기와 경조사 같은 사정을 함께 고려
장기 미접은 미리 알리면 예외운영 중 추가 — 게임사 이슈로 쉬는 사람과 현실 사정이 겹치는 것을 보고 고침

03개선 제안과 검증 방법

레이드 진입 화면에서 권장 준비 조건과 현재 상태를 나란히 보여 주고, 전투 성과 외의 기여 방법도 함께 안내하는 방안입니다.

안내가 많아지면 화면이 복잡해질 수 있으므로, 신규 이용자가 안내만으로 조건을 이해하는지와 어느 단계에서 진입을 포기하는지를 관찰해 효과를 확인해야 한다고 봅니다.
